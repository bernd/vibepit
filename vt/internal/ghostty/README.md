# libghostty-vt (WebAssembly, translated to Go)

`internal/wasmvt/ghostty-vt.wasm` is libghostty-vt built for
`wasm32-freestanding` with `-Doptimize=small` and `-Dcpu=generic` at the commit
in `internal/wasmvt/GHOSTTY_COMMIT`, plus the patches in `patches/`.
`GHOSTTY_COMMIT` also records the Zig version and the sha256 of the
`.wasm`; `TestProvenance` fails if they don't match.

`internal/wasmvt/ghostty_vt.go` is wasm2go's translation of that `.wasm`,
generated by the `go:generate` line in `internal/wasmvt/doc.go` with the
wasm2go version pinned in `go.mod`. Never edit it.
`TestGeneratedCodeIsCurrent` regenerates it and fails on any difference.
The `.wasm` is not embedded in the binary; it is the input and the
provenance record.

`-Dcpu=generic` matters: without it ghostty enables `simd128`, and wasm2go
fails with `unsupported opcode (SIMD)`.

## Patches

| Patch | Why | Upstream |
|---|---|---|
| `0001-formatter-content-none.patch` | Extras-only formatting (`GHOSTTY_FORMATTER_OPT_CONTENT_NONE`) | not yet proposed |
| `0002-formatter-origin-mode-without-modes.patch` | Cursor relative to the scroll region under DECOM without the modes extra | not yet proposed |
| `0003-wasm-max-memory.patch` | `-Dwasm-max-memory` build option for the module's memory limit | not yet proposed |

Delete a patch once an upstream commit includes it. Patch 0001 numbers its
option 1000, outside upstream's sequential range, so a future upstream
option can't take the value. Upstream's version of
the origin-mode fix (23c7a3e5a) only applies when the output also restores
the modes, which vibepit's restores don't ask for, so 0002 keeps the rest.

## Upgrading

Normally the `ghostty-wasm` workflow does this weekly and opens a PR on
the `ghostty-wasm-update` branch. It builds the newest libghostty-vt
release, the commit of the highest `vt-X.Y.Z` tag, and skips the run when
that is already pinned. Upstream's `main` is the next minor's development
branch, so it is never built unless asked for. A manual run takes a commit
or a `vt-X.Y.Z` tag. It needs "Allow GitHub Actions to create
and approve pull requests" under Settings → Actions → General → Workflow
permissions; without it the first run fails at `gh pr create`.

The build and tests run in a job with a read-only token, because they run
upstream's build scripts and the new generated code. A second job opens the
PR from the build's `ghostty-wasm` artifact, which also holds the test
output, the benchmarks and any fuzz crasher (under `testdata/fuzz/`). The
crasher is not in the PR: download it from the workflow run.

Fix a failing update by pushing commits to `ghostty-wasm-update`. While the
branch has commits by anyone other than `github-actions[bot]`, the weekly
refresh doesn't touch it, since its forced push would drop them. It
comments on the PR instead, with the ghostty commit it would have built.
Delete the branch after merging or closing the PR: human commits that main
doesn't contain by hash (after a squash merge, say) keep refreshes off.

By hand:

1. `make ghostty-wasm GHOSTTY_COMMIT=<sha>` (needs Zig 0.17). It also
   regenerates `ghostty_vt.go`.
2. `go test ./vt/internal/ghostty/...`. Failure categories:
   - **Compile error in this package**: an export was removed or changed
     its signature, or the module gained an import (`wasmvt.New` then
     takes arguments). Adapt `instance.go`.
   - **Layout or enum** (`TestABIMatchesTypeJSON`): update `abi.go`.
   - **Mode table** (`TestModeTableComplete`): update `Modes` in `abi.go`,
     then decide whether the overlay must reconcile the new mode.
   - **Round trip or getter**: a regression. Don't adopt the build, or
     adapt `vt` and document why.
   - **Golden diff** (`TestFormatGolden`): review the change, then rerun
     with `-update`.
   - **Known gap** (`TestKnownGaps`): upstream closed a gap. Remove
     vibepit's own emission of that state.
   - **Effects** (`TestQueryAnswers`): decide whether the new answer is
     safe to forward to the app while a prompt shows.
   - **Patch does not apply** (`build-wasm.sh` exits 3): rebase the patch,
     or drop it if upstream merged it.
3. `go test -run '^$' -fuzz FuzzVTWrite -fuzztime 5m ./vt/internal/ghostty`
4. `go test ./...`
5. Record `BenchmarkVTWrite` before and after, and the sizes of the
   `.wasm` and `ghostty_vt.go`, in the PR.

## Upgrading wasm2go

1. `go get -tool github.com/ncruces/wasm2go@<version>`
2. `go generate ./vt/internal/ghostty/internal/wasmvt`
3. Steps 2–5 above. If `memory.go` stops compiling, the generated code
   renamed its memory-limit constant: follow the rename.

## Memory limit

Each instance's linear memory is capped at 256 MiB (`vt.MemoryLimit`).
Since v0.4.19, wasm2go turns the module's declared maximum memory into a
constant, so the cap is set at link time: `build-wasm.sh` passes
`-Dwasm-max-memory`, which patch 0003 adds. It can't differ per
terminal. `TestMemoryLimitIsBuiltIn` fails on a module built without it.

A dependency update that bumps wasm2go without step 2 fails
`TestGeneratedCodeIsCurrent`.

## Known limit

Runaway recursion in the module is a fatal Go stack overflow that no
`recover` catches, so it kills the process. The fuzz test is the guard. If
it ever triggers, report it upstream with the input.

## Building inside a vibepit sandbox

Zig's package fetcher can fail through the proxy with
`HttpConnectionClosing` or an HTTP 400 or 403. Download each missing
dependency with `curl -LO` (git dependencies with `git clone` at the
pinned commit), and build again until nothing is missing. It needs
github.com, deps.files.ghostty.org and codeberg.org.

Zig 0.17.0's fetcher can also crash through the proxy with `General
protection exception` while it fetches packages in parallel. Unpack every
dependency first: all `.url`/`.hash` pairs in `build.zig.zon` and
`pkg/*/build.zig.zon` point to deps.files.ghostty.org.

Zig 0.17 unpacks packages into `zig-pkg/<hash>` in the ghostty checkout,
and `zig fetch <file>` caches a tarball that unpacks to a different hash,
so the build then fails with `hash mismatch`. Run `zig fetch <file>` only
to print the hash, and unpack the archive into `zig-pkg/<hash>` yourself,
without its top-level directory if it has exactly one (`git archive HEAD`
for a git dependency). Some archives, such as the fonts and dcimgui, have
several top-level entries; unpack those as they are.
